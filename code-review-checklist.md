# Чек-лист код-ревью (Вариант 4)

## 1. Обязательные проверки в каждом pull request
- [ ] Логика корректна, граничные значения обработаны (например, ровно 5000 и 10000 в шкале скидок).
- [ ] Некорректные входные данные обработаны (отрицательные числа, пустые значения).
- [ ] Для новой логики добавлены тесты, автоматическая проверка (CI) пройдена.
- [ ] Нет закомментированного и отладочного кода (console.log, временные заглушки).
- [ ] Имена переменных и функций осмысленные, «магические числа» вынесены в константы.
- [ ] Код соответствует стилю проекта, сообщения коммитов — Conventional Commits.
- [ ] Описание PR заполнено: что сделано, как проверить, связанные задачи.

## 2. Объём pull request
- Желательно не более 200–400 изменённых строк в одном PR.
- Один PR — одна логически завершённая задача; крупные задачи делятся на несколько PR.

## 3. Приоритизация комментариев
| Префикс | Значение | Блокирует слияние |
|---|---|---|
| blocking: / must fix: | ошибка, уязвимость, отсутствие тестов | да |
| question: | уточняющий вопрос автору | до ответа автора |
| nit: | мелкое замечание по стилю | нет |

## 4. Время реакции ревьюера (SLA)
- Первая реакция на запрос ревью — в течение 1 рабочего дня.
- Повторное ревью после правок — в течение 4 рабочих часов.
- Срочные исправления (hotfix) — в течение 1 часа.
